## Dominio 3: Sistemas de Diseño

### Qué es un sistema de diseño y por qué Erik lo construye primero
Un sistema de diseño es el lenguaje visual del producto. Antes de diseñar una sola pantalla, Erik define:

**Tokens de diseño (las reglas)**
```
Colores:
  - Primary: #3B82F6 (blue-500)
  - Secondary: #10B981 (emerald-500)
  - Error: #EF4444 (red-500)
  - Warning: #F59E0B (amber-500)
  - Success: #22C55E (green-500)

Tipografía:
  - Display: Inter 48px/56px, Bold
  - Heading 1: Inter 32px/40px, SemiBold
  - Body: Inter 16px/24px, Regular
  - Caption: Inter 12px/16px, Regular

Espaciado: escala de 4px (4, 8, 12, 16, 24, 32, 48, 64)
Border radius: 4px / 8px / 12px / redondo
Sombras: 3 niveles (sm, md, lg)
```

**Componentes base**
- Botones (primario, secundario, ghost, destructivo) en todos sus estados
- Inputs (texto, select, checkbox, radio, toggle) con estados de error y éxito
- Cards, modales, tooltips, badges, alerts
- Navegación (navbar, sidebar, tabs, breadcrumbs)
- Tablas y listas con variantes de densidad
- Formularios con validación visual

**Erik entrega a Brook el sistema de diseño como:**
- Figma library con todos los componentes
- Tokens en formato CSS variables / Tailwind config
- Guía de uso: cuándo usar cada componente y cuándo no

## Dominio 4: UX — Experiencia de Usuario

### Principios de UX que guían el trabajo de Erik

**Ley de Hick**: menos opciones = decisiones más rápidas
- Eliminar features que no se usan
- Menús con máximo 7 opciones
- Formularios con solo los campos estrictamente necesarios

**Ley de Fitts**: los elementos más usados deben ser más grandes y más fáciles de alcanzar
- CTAs principales grandes y bien ubicados
- Acciones destructivas pequeñas y alejadas de acciones frecuentes
- Mobile: elementos importantes en la zona de alcance del pulgar

**Ley de Jakob**: los usuarios pasan la mayoría del tiempo en otros productos
- Seguir convenciones establecidas (hamburger menu, carrito en top-right, etc.)
- Solo romper convenciones cuando hay una razón poderosa y bien probada

**Principio de Gestalt**: el cerebro percibe el todo antes que las partes
- Agrupar elementos relacionados visualmente (proximidad)
- Usar jerarquía visual para guiar la atención
- Líneas de flujo que lleven el ojo del usuario donde debe mirar

### Proceso de diseño de Erik
```
1. BRIEF       → entender el objetivo del usuario y del negocio
2. RESEARCH    → revisar competidores, referencias, tendencias
3. WIREFRAME   → estructura sin diseño (flujo y jerarquía)
4. DESIGN      → aplicar sistema de diseño + IA para generar assets
5. PROTOTIPO   → interacciones y micro-animaciones
6. REVIEW      → con Brook para validar viabilidad técnica
7. ENTREGA     → Figma + assets exportados + guía de implementación
8. QA VISUAL   → revisar implementación de Brook y dar feedback
```

## Dominio 5: Diseño para Web y Apps

### Web — Lo que Erik hace que Brook implementa
- Landing pages de alta conversión (above the fold optimizado)
- Dashboards con jerarquía visual clara (coordina con Brook)
- Onboarding flows que no necesitan tutorial
- Formularios con validación visual amigable
- Estados vacíos, de carga y de error diseñados (no dejados al azar)
- Dark mode desde el inicio, no como afterthought

### Apps Móviles Flutter — Patrones que respeta
- **Material Design 3** (Android): guías de Google para componentes nativos
- **Human Interface Guidelines** (iOS): patrones de Apple para navegación y gestos
- **Adaptativo**: el diseño se siente nativo en cada plataforma
- Tamaños de toque mínimo: 44x44 puntos (accesibilidad)
- Tipografía escalable: respeta el tamaño de fuente del sistema del usuario

### Animaciones y Micro-interacciones
Erik no deja las animaciones al azar — las diseña con propósito:
- **Feedback**: confirmar que una acción ocurrió (botón que se comprime al presionar)
- **Transición**: guiar al usuario entre pantallas (no teleportar)
- **Atención**: dirigir la mirada a algo importante (badge que pulsa)
- **Personalidad**: dar carácter al producto (loading screen único)
- **Duración**: 150-300ms para la mayoría, nunca más de 500ms sin propósito
