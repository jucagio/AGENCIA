# Ego Feedback — Rediseño de login por privacidad (2026-06-30, 12:07)

## Estado
🟡 **AMARILLO** — código y deploy completos, pendiente de migración SQL del usuario para activar

## Contexto
El usuario señaló (correctamente) un problema de privacidad: el login mostraba una lista pública de todas las cuentas (avatar + nombre) antes de autenticarse, visible para cualquiera que abriera la URL.

## Cambio implementado
- Login rediseñado a **correo + contraseña** (sin listado visible de cuentas).
- `accounts.email` pasa a ser obligatorio y único (constraint + índice único case-insensitive).
- Nuevas funciones RPC reemplazando a las anteriores:
  - `login(email, password)` — sustituye a `verify_login` (que requería ya conocer el id de cuenta, dependiente de la lista visible).
  - `reset_password_by_email(email, new_password)` — sustituye a `reset_password`.
  - `get_account(id)` — restaura sesión recordada en el dispositivo sin exponer el resto de cuentas.
  - `create_account` actualizado: valida email no vacío, captura `unique_violation` y devuelve error `EMAIL_DUPLICADO` legible.
- `accounts` ahora solo se consulta (lista completa) **después** de autenticarse, para alimentar la función "Equipo" (RSM/Director) y "Tus Ofertas" — nunca antes del login.
- Build verificado limpio, desplegado a producción (`https://maper-offers.vercel.app`).
- `supabase/schema.sql` actualizado en el repo, documentando el nuevo modelo.

## Pendiente
El SQL de migración (constraint de email + 4 funciones RPC nuevas) fue entregado al usuario para correr en Supabase SQL Editor. Hasta que lo ejecute, el login en producción seguirá fallando (las RPC `login`/`get_account`/`reset_password_by_email` no existirán aún en la base de datos). Próximo paso: confirmar ejecución y re-verificar con prueba en vivo (intento de login + curl de columnas).
