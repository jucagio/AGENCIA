## Avance sobre el hallazgo anterior
El usuario corrió la consulta de diagnóstico solicitada (`information_schema.column_privileges` para `accounts`) y confirmó que `anon` y `authenticated` tienen `SELECT` sobre **todas** las columnas, incluida `password`.

**Causa raíz identificada:** el primer script de remediación solo revocó `insert, update, delete` a nivel de tabla, pero nunca revocó el `SELECT` de tabla completa. En PostgreSQL, un `REVOKE SELECT (columna) ...` no tiene efecto si ya existe un grant de `SELECT` a nivel de tabla completa (que Supabase otorga por defecto a `anon`/`authenticated` al crear cualquier tabla nueva en `public`). El privilegio de tabla completa sigue cubriendo todas las columnas independientemente del revoke granular.

## Corrección entregada
```sql
revoke select on accounts from anon, authenticated;
grant select (id, nombre, cargo, telefono, email, rol, created_at) on accounts to anon, authenticated;
```
Se actualizó también `supabase/schema.sql` en el repo con esta corrección y un comentario explicando la causa, para que futuras tablas con datos sensibles no repitan el mismo error.
